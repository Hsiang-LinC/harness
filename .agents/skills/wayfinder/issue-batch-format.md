# Plain-issue batch format

`harness issue publish --file <batch>` reads this JSON
. It
publishes a wayfinder map, its child tickets, their `wayfinder:*` labels and
their blocker edges; it needs no claim.

```json
{
  "issues": [{ "id": "<new issue UUID>", "title": "…", "description": "…",
               "parent": "<optional issue UUID>", "labels": ["<optional label UUID>"] }],
  "edges":  [{ "blocker": "<issue UUID>", "blocked": "<issue UUID>" }]
}
```

- Generate each new issue's UUID yourself. A `parent` or an edge end is a
  batch issue or one that already exists.
- `labels` are label UUIDs: read the `wayfinder:*` labels by name with the
  connector's label listing for the policy's team. A triage role label is
  refused.
- At most 50 issues, 200 edges and 10 labels per issue; `issues` and `edges`
  are both present, and at least one is non-empty. No description starts with
  `Generated by Harness`.
- It only adds, and a rerun converges: an existing batch issue must have the
  batch's title and parent, and its description is written only at creation.
- Linear identifiers (such as `ENG-12`) exist only after the publish. To link
  tickets in the map's body, edit the published map afterwards through the
  connector, as the seed's per-operation paths allow.
